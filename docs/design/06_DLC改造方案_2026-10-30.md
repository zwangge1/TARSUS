# 06 · TARSUS 的 DLC 改造方案（2026-10-30）

> 决定（用户 10-30）：主线框架用 **DeepLabCut 3（PyTorch 后端）**；代码一律从 GitHub clone 官方仓库，在原有代码上修改，不另起炉灶。Lightning Pose 只作后期可选的泛化实验。

## 0. 符号与术语（先读）

| 符号 | 含义 |
|---|---|
| `hip`、`knee` | 髋、膝。羽毛下看不见，人工标注是估计值 |
| `itj` | intertarsal joint，胫跗骨与跗跖骨之间的关节，就是鸟外露的"反向膝"。Duong 标注里叫 `ankle` |
| `tmp` | 跗跖骨与趾之间的关节。Duong 标注里叫 `foot` |
| `toe` | 中趾趾尖。Duong 标注里叫 `foot_tip` |
| $\ell_{fem},\ell_{tib},\ell_{tmt}$ | 预测出的股骨、胫跗骨、跗跖骨的 2D 长度（像素），分别是 hip→knee、knee→itj、itj→tmp 的距离 |
| $r$ | 骨长对数比向量 $[\log(\ell_{fem}/\ell_{tmt}),\ \log(\ell_{tib}/\ell_{tmt})]$ |
| $s$ | 物种 |
| $\mu_s,\Sigma_s$ | 物种 $s$ 的先验：$r$ 的均值与协方差，来自形态数据库 |
| $\Sigma_{proj}$ | 2D 投影导致的额外散布（腿段转出画面会变短），从 Duong 标注帧估计 |
| $\lambda$ | 先验 loss 的权重 |
| $\epsilon$ | 容差：马氏距离在 $\epsilon$ 以内不罚 |
| SA | `superanimal_bird`，DLC 官方鸟类预训练模型（ResNet-50，42 点） |

## 1. 一句话

在 DLC 3 的 heatmap 头上加一项**物种条件化骨长比先验 loss**，并把同一个先验装进 SuperAnimal video adaptation 的**伪标签过滤器**。看得见的点（itj、tmp、toe）由人工标注或伪标签监督；看不见的点（knee、hip）在没有标注的帧上只受先验约束。这样 DLC 就能在大量未标注的鸟视频上自标注膝和髋。

## 2. 标注规范

沿用 Duong 的 16 点 DLC 项目（`FFY\duong_data\deeplabcut\bird-landing-Duong-2025-06-29`），**点名不改**，避免动 DLC 项目文件；只在 TARSUS 代码里维护一张解剖名映射：

| DLC 点名（Duong） | TARSUS 解剖名 | 可见性 |
|---|---|---|
| `left/right_hip` | hip | 不可见 |
| `left/right_knee` | knee | 不可见 |
| `left/right_ankle` | itj | 可见 |
| `left/right_foot` | tmp | 可见 |
| `left/right_foot_tip` | toe | 可见 |
| beak、head、neck_base、shoulder、tail_base | 躯干与头 | 可见 |

已核实（10-30）：759 帧人工标注里，膝→踝 / 踝→足 的 2D 比值中位数为 1.35 到 1.65（四个物种），与胫跗骨/跗跖骨比一致，说明 `knee` 是真膝、`ankle` 是 itj，定义没有混用。

## 3. 改动清单（全部在官方代码上修改）

DLC 3 训练一步的调用链（源码核实）：
`runners/train.py::PoseTrainingRunner.step` → `model.get_target(outputs, batch["annotations"])` → `model.get_loss` → 每个 head 的 `BaseHead.get_loss`（`models/heads/base.py`），由 `WeightedLossAggregator` 把 heatmap 和 locref 两项加起来。SA 与 Duong 模型的头都是 `HeatmapHead` + `HeatmapPredictor`（`config/base/head_topdown.yaml`：heatmap 用 WeightedMSE，locref 用 WeightedHuber，权重 0.05）。

| # | 文件（官方路径） | 改什么 | 为什么 |
|---|---|---|---|
| M1 | `pose_estimation_pytorch/data/dataset.py`（`__getitem__`）、`data/collate.py` | 在 `batch["annotations"]` 里加 `species_id`（按图片路径里的视频名查 `species_map.csv`） | 先验要知道每张图是什么鸟。目前 batch 只有 path、keypoints、scales 等 |
| M2 | `models/target_generators/heatmap_targets.py` | 在 `HeatmapGaussianGenerator` 上加一个子类 `HeatmapGaussianPriorGenerator`：照常生成 heatmap/locref 目标，额外把 `species_id`、`scales`、`offsets` 传进 targets | 损失函数只看得到 `outputs` 和 `targets`，所以要靠目标生成器把物种信息带进去 |
| M3 | 新文件 `models/criterions/bone_prior.py`，在 `CRITERIONS` 注册 `BoneRatioPriorCriterion` | 用 soft-argmax 加 locref 从 heatmap 得到可微坐标，按 §4 公式计算先验 loss | 现有 predictor 用 argmax，不可微，不能直接拿来算 loss |
| M4 | `models/heads/simple_head.py` | 加子类 `HeatmapPriorHead(HeatmapHead)`，重写 `get_loss`：先调父类拿到 heatmap 与 locref 的 loss，再加 $\lambda\mathcal{L}_{prior}$ 一起送进 aggregator | 先验 loss 要同时用 heatmap 和 locref 两个输出，单个 criterion 只能拿到其中一个 |
| M5 | 新配置 `config/base/head_topdown_tarsus.yaml` | 复制 `head_topdown.yaml`，把 type 换成 `HeatmapPriorHead`，加上 `prior:` 段（先验文件路径、$\lambda$、$\epsilon$、关节索引、$\Sigma_{proj}$） | 全部走配置，组 A 到 D 只是配置不同 |
| M6 | `utils/pseudo_label.py::dlc3predictions_2_annotation_from_video` | 在原有的 `pose_threshold`（置信度置零）之后，加骨长比马氏距离过滤：超过 $k$ 时把该侧的 hip、knee 置为不可见（可见点保留） | 替换文档 03 §1.1 指出的"只有置信度阈值"的过滤器 |
| M7 | `modelzoo/video_inference.py::video_inference_superanimal` | 透传 `prior_file`、$k$ 两个参数到 M6，再透传 head 配置到 `adaptation_train` | 让 video adaptation 的微调也带先验 loss |

不改的部分：backbone、检测器、数据增强、评测代码、snapshot 管理，全部用官方实现。

**未标注帧怎么进训练**（不用改过滤逻辑）：官方 `filter_annotations` 会丢掉所有点都不可见的标注（`data/base.py:303`、`data/cocoloader.py:326`）。我们的未标注帧来自伪标签，itj、tmp、toe 是可见的，所以不会被丢；knee、hip 设为不可见，heatmap loss 在这两个点上自动置零（`gradient_masking: true`），这两个点就只受先验 loss 约束。

## 4. 先验 loss

可微坐标：对关节 $j$ 的 heatmap $H_j$ 做温度为 $\beta$ 的 softmax，再对网格坐标加 locref 偏移取期望：

$$\hat p_j = \text{stride}\cdot\sum_{u}\operatorname{softmax}(\beta H_j)_u\,\big(u + \sigma_{loc}\,\Delta_j(u)\big)$$

其中 $\sigma_{loc}=7.2801$ 是 DLC 默认的 `locref_std`，$\Delta_j$ 是 locref 输出。坐标除以 `scales`，还原到原图像素后再算骨长，避免 top-down 裁剪时的非等比缩放改变比值。

每一侧腿：

$$r = \Big[\log\frac{\ell_{fem}}{\ell_{tmt}},\ \log\frac{\ell_{tib}}{\ell_{tmt}}\Big],\qquad d = \sqrt{(r-\mu_s)^\top(\Sigma_s+\Sigma_{proj})^{-1}(r-\mu_s)}$$

$$\mathcal{L}_{prior} = \max(0,\ d-\epsilon),\qquad \mathcal{L} = \mathcal{L}_{heatmap} + 0.05\,\mathcal{L}_{locref} + \lambda\,\mathcal{L}_{prior}$$

用比值而不是绝对长度，是因为鸟离相机的远近未知，比值不受尺度影响。

## 5. 先验文件 `prior_v0.json`

- 格式：`{species: {mu: [2], Sigma: [[2,2]], source: ..., n: ...}}`，外加属级、科级的回退条目。
- 数据来源（已确认在手）：鸭、鹅、天鹅用 `EvoWM/data/raw/watanabe2017`（雁鸭科），交叉核对 `eliason2023/S1_limb_data.csv`；鹈鹕用 `eliason2023`（有 *Pelecanus*）。
- $\Sigma_{proj}$：用 Duong 759 帧人工标注的 2D 比值，减去对应物种的 3D 比值分布后估计。
- 后续由 04 §7 的 L1 到 L4 全鸟类先验库替换，接口不变。

**缺口**：Duong 的 `Videos.xlsx` 只有鸭写了物种（Mallard）；鹅、天鹅、鹈鹕没有写种名。v0 有两个处理办法：
- 你按视频补种名（看链接或画面即可，约 70 段）；
- 或者先退到属级先验（*Anser/Branta*、*Cygnus*、*Pelecanus*），协方差放宽。

## 6. 训练起点

- 用 DLC 自带的 `keypoint_matching`（`utils/pseudo_label.py:141`），在 759 帧上跑 SA，自动生成 Duong 16 点到 SA 42 点的 conversion table。这一步同时回答"SA 的 `leg`、`tibia`、`foot` 到底落在哪个关节上"。
- 用 `modelzoo/weight_initialization.py::build_weight_init(..., with_decoder=True)`，按 conversion table 载入 SA 权重。SA 没有的点（knee、hip）怎么初始化，**要在跑通时核实**。如果官方不支持，就退回只载入 backbone。

## 7. 实验组

| 组 | 配置 | 回答的问题 |
|---|---|---|
| A0 | Duong 原模型（`dlc-models-pytorch` 里已有的 snapshot） | 历史基线 |
| A | 官方 DLC，SA 初始化，只用人工标注 | 框架基线 |
| B | A + $\mathcal{L}_{prior}$，全鸟统一的 $(\mu,\Sigma)$ | "加骨长约束"本身有没有用 |
| C | A + $\mathcal{L}_{prior}$，按物种条件化 | **论文核心：C 比 B 好多少** |
| D | C + 未标注视频帧（伪标签经 M6 过滤），即 video adaptation 带先验 | 自标注能不能进一步提升 |

- 评测：knee、hip 的 PCK@0.1（以跗跖骨像素长度归一化），以及可见点的 RMSE；同一段视频内骨长比的 CV。
- 物种留一：鸭、鹅、鹈鹕、天鹅轮流做测试集，看先验能否迁移到训练时没见过的物种。
- 每组至少 2 个种子。
- 必须如实写明：knee、hip 的参考答案是人工估计的，不是 X 光真值。

## 8. 预注册判据（写进 `docs/prereg/seg_w1.md`，跑之前定死）

1. M6 过滤：伪标签的骨长比 CV 下降 ≥20%，可见点 RMSE 不变差。
2. C 对 A：knee PCK@0.1 提高 ≥10 个百分点（物种留一的平均值）。
3. C 对 B：knee PCK@0.1 提高 >0，并且在 ≥3/4 个留一折上方向一致。

1、2 都过就全力推进。2 不过说明先验太松，回到只做先验库。
